# 原生精修制作流程

这份说明记录 R3 的制作链，方便继续迭代：**原版参考 → 内置 image_gen 局部改动作 → 本地透明化 → 统一缩放与锚点 → 原生打包 → 浏览器审阅 → 手动 Codex 验收**。步骤说明不是通过报告；当前结果以 `reviews/` 为准。

所有命令均在仓库根目录运行。新一轮请更换 `iteration-03` 编号，并保留旧源片、提示词和失败证据。

## 1. 准备依赖和原版参考

```bash
python3 -m venv .venv
source .venv/bin/activate
python3 -m pip install -r requirements.txt
python3 tools/prepare_reference.py \
  --base assets/upstream/yanami-anna/spritesheet.webp \
  --output assets/source/native-reference
```

工具从原版 192 × 208 格取图，放大两倍后放进 512 × 512 绿底源格的 `(64,48)` 位置，生成 3 × 2 参考片。`identity-six.png` 将同一张原版正面图重复六次；`idle-original.png`、`waiting-original.png`、`running-original.png` 则保留原版各状态的六帧。这个步骤只裁格与缩放，不重画角色。

## 2. 用内置 image_gen 局部改动作

以 `assets/source/native-reference/identity-six.png` 为实际编辑目标，使用 Codex 内置 image_gen。提示词已经保存在：

- [iteration-03/prompts.json](../assets/source/iteration-03/prompts.json)：running 的小本子和轻微书写。
- [iteration-03/prompts-extra.json](../assets/source/iteration-03/prompts-extra.json)：idle 的轻呼吸/半眯眼，以及 waiting 的微手部动作。

要求保持原版脸、头身比、发型、制服、鞋和格内位置，仅改对应局部。源片使用有意保留的纯绿 `#00FF00` 背景；这里不把 RGB 绿底当成已透明的成品。输出分别保存为 `assets/source/iteration-03/{idle,waiting,running}.png`。

image_gen 是生成步骤，同一提示词不保证逐像素相同。因此可复现的重点是保留确切输入、提示词、实际输出及哈希；从已经保存的源片继续后续本地处理。没有对应命令行脚本，不应编造一条“自动重新生成相同图”的命令。

先按[设计约束](design.md)和[源图审阅记录](../reviews/visual-iteration-03.md)确认身份与肢体，合格后再透明化。

## 3. 本地生成真正的透明背景

本轮已获用户授权使用本地脚本处理图像。下面的工具只负责透明背景与边缘，不修脸、改姿势或判断角色是否合格：

```bash
python3 tools/extract_matte.py \
  assets/source/iteration-03/idle.png \
  assets/source/iteration-03/waiting.png \
  assets/source/iteration-03/running.png \
  --output-dir assets/source/iteration-03-alpha \
  --report reviews/iteration-03-alpha.json \
  --grid 3x2 \
  --background '#00ff00' \
  --hole-zones all \
  --min-hole 1
```

本轮默认参数包括容差 55、去色溢出阈值 16、边缘羽化 0.45；完整参数与文件哈希写入报告。输出为 RGBA PNG，同时生成深浅底联系表供人工检查。重点看发梢小孔、袖口、裙摆、鞋，以及笔和手之间：既不能残绿，也不能把原本的白衣、眼睛或细线误删。

脚本成功输出不等于边缘审阅通过。出现残绿、孔洞或细节丢失，应在新修订中调整参数并重新审阅，保留旧报告。

## 4. 恢复原生尺寸，统一锚点

源片每格 512 × 512，角色是从原生格放大两倍后放进去的。直接对整格使用 contain 会把角色缩小；这一链应先用固定裁剪恢复原生格：

```bash
python3 tools/align_frames.py \
  assets/source/iteration-03-alpha/idle.png \
  assets/source/iteration-03-alpha/waiting.png \
  assets/source/iteration-03-alpha/running.png \
  --output-dir assets/source/iteration-03-native \
  --report reviews/iteration-03-native.json \
  --grid 3x2 \
  --crop 64 48 384 416 \
  --scale 0.5 \
  --baseline 203
```

工具对全部 18 帧使用相同裁剪和 0.5 倍缩放，再根据缩放后底边中位数计算**一个共同纵向平移**；目标底边 203 是 bbox 的排他性下边界。它不会逐帧重新缩放或把每只脚单独钉住。实际平移值由报告记录，不凭肉眼另加偏移。

输出每张为 576 × 416 的 RGBA 六帧片，即每格恰好 192 × 208。若固定裁剪或统一平移会切断角色，工具应报错，返回源素材定位问题；不要通过逐帧缩放掩盖比例差异。

## 5. 打包成原生静态 WebP

```bash
python3 tools/pet_tool.py build \
  --base assets/upstream/yanami-anna/spritesheet.webp \
  --output pets/yanami-anna-refined \
  --fit native \
  --replace idle assets/source/iteration-03-native/idle.png 3x2 \
  --replace waiting assets/source/iteration-03-native/waiting.png 3x2 \
  --replace running assets/source/iteration-03-native/running.png 3x2

python3 tools/pet_tool.py validate pets/yanami-anna-refined \
  --json reviews/iteration-03-package-validation.json
```

产物为 `pet.json`、**单帧无损 WebP** 图集和 `validation.json`。图集保持 1536 × 2288、8 × 11 格；只有三个指定状态被替换，其余有效格逐像素核对保留。原版多出的 idle 第七格被清空，最终满足 73 个有效格、15 个透明余格的本机契约。

保留包内构建报告以及独立检查报告：前者还记录输入来源、替换行和原版保留核对。无损编码指最终打包不再作有损压缩，不代表前面的生成或尺寸处理没有改变像素。

## 6. 看最终图集，再进入真实 Codex

```bash
python3 -m http.server 8765 --bind 127.0.0.1
```

打开 [本地预览](http://127.0.0.1:8765/preview/)，核对原版/候选、深浅底、原生格和小尺寸，再看原速循环。idle 一轮 6.6 秒，waiting 一轮 1.01 秒，running 一轮 0.82 秒；非 idle 三轮后回待机。慢放和循环审阅用于找问题，不能代替原生播放。[预览说明](../preview/README.md)

满足自动检查与视觉门槛后，才进入候选安装步骤：

```bash
python3 tools/pet_tool.py install pets/yanami-anna-refined
```

该命令只复制独立候选包并核对哈希，不选中宠物。本次环境不能自动控制 Codex 界面，用户需在 Mini / My pets 手动选择“八奈见杏菜·精修”、显示 Mini，并按[实际验收标准](acceptance.md#第三层真实-codex-验收)观察和反馈。未完成真实验收时继续保持 candidate，不能把安装结果写成视觉通过。

## 为什么保留前两轮失败稿

R1 将棋盘画进 RGB 图片，没有真正透明背景；同时脸型、头身比、制服画法与保留的原版动作差异明显。R2 让 image_gen 提取透明背景后仍是 RGB 棋盘，running 第三格还出现偏离书写的手势，身份差异也未解决。

这些证据保存在 [iteration-01.md](../reviews/iteration-01.md)、[visual-iteration-01.md](../reviews/visual-iteration-01.md)、[iteration-02.md](../reviews/iteration-02.md) 及各轮源片中。R3 回到原版固定参考、只改小动作，并使用获授权的本地透明化；后续修订不能覆盖旧证据或把旧失败改写成通过。每轮记录规范见[验收与迭代](acceptance.md#每轮审阅记录)。
