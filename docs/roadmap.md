# 迭代路线

路线按验收结果推进，不按功能数量推进。当前首要交付是可复查、可回退的原生精修 candidate；任何后续阶段都不能把前一阶段未通过的问题写成已解决。

| 阶段 | 范围 | 进入下一阶段的条件 |
|---|---|---|
| v0.1 candidate | idle / waiting / running 各六帧；其他动作保留；构建、检查、预览与独立安装目录 | 三层验收完成，真实 Codex 中用户确认可接受 |
| v0.1 修订 | 按具体失败项修脸型、肢体、道具、锚点、边缘与节奏 | 修复有新候选和复查证据，无已知硬门槛失败 |
| v0.2 原生完整动作 | 逐行精修挥手、固定交互、异常、review，再处理左右移动与 16 朝向 | 每行单独验收，新旧风格一致，全部原生动作可用 |
| 后续原生衣装 | 少量完整衣装包，保持同一脸型、比例与锚点 | 每套都有完整动作与预览，手动切换方式清楚 |
| 可选 animated atlas 实验 | 单独实验分支验证连续微动作，始终保留静态包 | 实机验证任意相位切入、缓存、资源占用、减少动态效果；未经验证不替代静态版 |
| 可选独立伴侣 | 若用户明确希望投喂、对白、收藏或真实记忆，再评估额外程序 | 明确 Mac 支持、事件来源、资源许可、退出与回退；独立立项 |

## v0.1 的完成定义

产物可重复构建；三种精修动作仍保留原版 Yanami 的身份；其余状态没有意外变化；自动检查、预览和真实 Codex 验收都有记录；用户能随时切回原版。没有真实 Codex 反馈时只能说“候选已准备好”，不能说“精修完成并通过实机”。

## 优先修什么

身份与肢体错误优先于帧数和装饰；尺度、锚点与透明边缘优先于道具；原速观看的节奏优先于慢放中的细节。若某个新动作比原版更吵或更不自然，可以退回原版并留下问题记录，保留另外两个确实通过的精修状态。

## 暂不承诺的能力

原生 `pet.json` 没有自由台词、语音、投喂、亲密度、天气换装或每种工具的独立动作接口。研究中的优秀项目可以提供设计灵感，但它们的运行时代码和平台能力不能通过增加素材字段移植进 Codex。具体参考与平台边界见[研究记录](research.md)。
