# Yanami 扩展方案：保留原版动作

日期：2026-09-10。状态：方案讨论，尚未实现。用户明确喜欢原版动作，后续主线停止重绘或替换这些动作。candidate-001 留作历史实验，不再等待其实际使用验收来推进新方向。

## 共同约束

原版图集作为只读基线；保留原来的姿势、帧顺序与默认节奏。新增动作是可关闭的独立动作包；点心、道具、台词、存档放进扩展层。扩展关闭后，原版仍可独立使用。不得把已完成素材管线的测试数量当作新玩法已经存在的证据。

原生宠物已有任务状态和多任务活动托盘，不把重复这些功能列成主要新增价值。[官方 Pets 文档](https://learn.chatgpt.com/docs/pets)

本机已核对的原生 pet.json 没有投喂按钮、收藏、对话或任意新增动作事件接口。[本机宿主格式](host-contract.md)只约束宠物素材，不意味着 Codex 整体没有扩展机制；当前已有 [Hooks](https://learn.chatgpt.com/docs/hooks)，但需单独验证本机桌面版实际发出的事件。

## 两种承载方式

| 方式 | 使用感受 | 能力边界 |
|---|---|---|
| 原生宠物 + 菜单栏小卡片 | 桌上继续显示原来的八奈见；需要投喂、看日记或布置房间时打开卡片 | 不控制原生宠物的动作；卡片可另用原图集展示互动。不能保证卡片自动跟随原生宠物移动 |
| 配套程序统一显示角色 | 配套窗口加载原版图集，在同一只角色上实现气泡、点击、拖拽物品和新增动作 | 需要独立 Mac 程序，并核对自己的播放时序；用户可手动隐藏原生 Mini，避免常驻两只 |

首个原型可先用卡片验证玩法。若核心需求是“直接和桌上的她互动”，应选择第二种方式。两者都不需要先重画原版人物。

## 1. 零食抽屉与收藏册

**体验**：主动打开抽屉，选择一种点心。卡片里的她用原有的开心、挥手或跳跃动作回应，留下一句短话；包装贴纸收入收藏。不是只显示“好感度 +1”，而是每种点心有少量不同内容。

**一个例子**：第一次给布丁，出现“这个可以留到休息的时候吃。”；再次选择同一种，收藏册保留第一次赠送日期，后续短句避免连续重复。这些为原创示例台词，并非原作台词。

**首版范围**：6 种食物图标、约 20 条固定短句、一本本地收藏册；赠送记录、偏好与关闭声音的选项。主动互动，不设计饿死、断签惩罚或必须持续工作的门槛。

**后续扩展**：点心组合、季节包装、特殊纪念贴纸；愿意增加新动作时，再追加“接点心”“吃一口”，不覆盖旧动作。

**投入与难点**：程序与素材投入适中，不需要语言模型，也不必先接入 Codex 事件。重复互动要有变化，但不能靠无穷数值让人机械刷取。

**验收**：重启后收藏仍在；多次点击不会重复扣取或重复发放；新动画关闭时原动作可用；连续几天有可辨识的新内容。

参考 [DyberPet 的食物偏好与互动资源规则](https://github.com/ChaozhongLiu/DyberPet/blob/f82126b4c860bfe194b7c2e0797a9882e6569ac7/docs/art_dev.md)及 [VPet 的食物动画组织](https://github.com/LorisYounger/VPet/blob/2e99a42ebeff71d792118f2e8de744b773042f8d/VPet-Simulator.Core/Graph/FoodAnimation.cs)。借鉴机制，不要求采用其平台引擎。

## 2. 你专注，她去便利店

**体验**：主动开始一段专注，她在配套卡片中出门采购。结束后留下一张小票、一件点心或一段短见闻。原生 Mini 可以继续照常显示；只有统一角色窗口模式才能让桌上同一只角色真的离开再回来。

**一个例子**：选择“便利店 / 25 分钟”，结束后带回一张写着“第二件半价，于是多拿了一个”的小票和一枚包装贴纸。小票进入方案 1 的收藏册。

**首版范围**：可暂停、取消并跨重启恢复的计时器；一个地点；约 12 条采购见闻、3 类纪念物。出门与回来复用原来的移动和挥手。

**后续扩展**：面包店、书店、自动贩卖机；地点对应不同小故事和摆件。用户中途取消不会被扣收藏，也不让更长的专注时长自动变成更高价值。

**投入与难点**：程序投入适中、人物美术需求低，主要精力是文案和少量道具。系统睡眠、重启、重复结束提醒需要处理。

**验收**：休眠恢复后剩余时间正确；每段专注只结算一次；结束只留一次提醒；能完全离线使用。

参考 [DockCat 外出事件与奖励生成](https://github.com/Auwuua/DockCat/blob/9dd4c4b678c68d7f5eb987ae9f284093e9d0d58d/DockCatApp/DockCat/Core/Outing/OutingRewardGenerator.swift)及[提醒队列](https://github.com/Auwuua/DockCat/blob/9dd4c4b678c68d7f5eb987ae9f284093e9d0d58d/DockCatApp/DockCat/Core/Reminder/ReminderQueue.swift)。

## 3. 桌角文学社

**体验**：打开一间小活动室：窗边、桌面、书架和点心角。八奈见继续使用原来的待机、行走、挥手和朝向。你可以贴一句便签，摆上采购得到的物品，切换白天或傍晚灯光。

**一个例子**：专注结束带回的布丁摆在桌面；完成一个自己认可的里程碑后，把日期写在墙上。下次打开还保持相同布置。

**首版范围**：一张场景、三个摆放位置、几件摆件、一张可编辑便签；角色仍用原图，不为了坐到椅子上临时重画整套姿势。需要坐姿、翻书时，作为后续可选动作。

**后续扩展**：收藏品陈列、节日布置、多个房间预设。场景与项目关联时先手动选项目，事件适配通过后再自动切换。

**投入与难点**：美术投入中等偏高，程序投入中等；主要问题是场景比例、遮挡和占用屏幕空间。隐藏窗口时停止无意义的持续渲染。

**验收**：原人物不会拉伸或被桌子挡住脸；布置重启后保留；小尺寸仍清楚；不会妨碍工作窗口操作。

参考 [vscode-pets 的主题场景与互动](https://github.com/tonybaloney/vscode-pets)、[Pixel Agents 的房间编辑与布局持久化](https://github.com/pixel-agents-hq/pixel-agents)。Pixel Agents 当前参考实现仍是 Claude Code，Codex 列为路线图，不作为现成的桌面 Codex 适配器。

## 4. 原版动作库 + 可选互动动作包

**体验**：所有旧动作保留。额外提供“递点心”“翻包找零钱”“整理蝴蝶结”等小表演，只有你点选相应互动时才播放。每个包可以单独禁用，原来的待机不会被替换。

**首版范围**：先追加一个互动，如“接点心”。把动作分为进入、表演、返回，播完回到原动作；提供原动作浏览菜单，便于确认没有被覆盖。

**后续扩展**：接点心、展示小票、躲到屏幕边等主题包。普通彩蛋设置较长冷却；新增动作不能不断抢占旧动作，也不能用一个新长循环接管整个待机。

**投入与难点**：代码投入中等、美术投入偏高。重点变成画风一致、手部与道具连续、退出时自然。上一轮的透明与制作工具仍可复用，但原生固定网格不能被当成无限动作槽。

**运行方式**：真正追加可触发的动作需要配套播放器；纯原生包没有任意加行和新触发按钮的接口。用户喜欢的默认时序要单独验证，导入旧图本身不保证新引擎播放完全相同。

**验收**：原 73 个实际使用格的像素与顺序不变；关闭新动作后保持默认播放；连续触发不会卡住；任一新增动作都可取消并返回。

参考 [VPet 的动作组织](https://github.com/LorisYounger/VPet)、[Ark-Pets 的动作组合与优先级](https://github.com/isHarryh/Ark-Pets/blob/b88c8625498ac1f857fa0841de8d183d37cefb9b/core/src/cn/harryh/arkpets/animations/AnimComposer.java)。只借鉴设计，不承诺直接采用 Windows 引擎。

## 5. 台词、偏好与共同日记

**体验**：她记得上次收到什么、收藏了哪些东西、你主动保存过哪些小事。点开“今天的文学社”能看到一张短日记；气泡短而低频，点开才继续说。

**一个例子**：你把“网站终于上线”保存为纪念，她在日记里写下一句庆祝；下次你打开同一纪念页，可以看到当时选的点心。事实来自存档，不由模型凭空推测。

**首版范围**：约 30 条原创台词、去重复与冷却、可查看/修改/删除的本地记忆项，先不接自由聊天。仅保存用户互动与明确确认的事件。

**后续扩展**：自由文字聊天、可选语音。若接模型，增加生成成本、延迟与角色口吻评估；模型表达可以灵活，但不能把虚构事件写成发生过的事实。保留原图集，无需先换成 Live2D。

**投入与难点**：固定台词版适中；聊天和语音版高。成败主要取决于文案与记忆质量，而不是对话字数。

**验收**：不重复播同一句；删除的记忆不会再被引用；未接入任务信息时不声称知道工作内容；声音和主动气泡都可关闭。

参考 [UniPet 将工作状态、行为与短句分离](https://github.com/ydyangdan/UniPet)以及 [AIRI 的聊天、语音与角色驱动架构](https://github.com/moeru-ai/airi)。AIRI 的部分记忆模块仍在开发，不把其路线图当作现成功能。

## 6. 项目纪念册与工作彩蛋

**体验**：扩展关注值得留下来的成果。一次对话结束后，你可以把它标记为“值得纪念”，保存一张项目卡片；重大里程碑解锁桌面摆件或点心包装。以后打开项目，看到它专属的小收藏。

**首版范围**：手动项目标签、里程碑标题与日期、本地纪念册；原来的宠物负责基础状态提示。这一版无需先监听所有任务。

**自动联动版**：验证桌面 Hooks 后，收集真实的开始、结束、中断等事件，提供待整理的活动条目。一次 Stop 只能证明轮次结束，不能直接证明代码完成、测试通过或部署成功；里程碑仍由明确结果或用户确认决定。

**后续扩展**：项目各自的点心、活动室布置和日记，按用户定义的成果解锁收藏。不要简单把 token 消耗做成奖励目标。

**投入与难点**：手动版较轻；自动版偏高，主要是当前桌面版本的事件覆盖、主任务与子任务区分、去重与恢复。自动挂件跟随原生宠物属于未验证实验，不作为首版承诺。

**验收**：两项并行任务不会混淆；子任务结束不误判全部完成；不能观察的状态显示未知；只有确认的里程碑才发放纪念物。

参考 [AgentPet 的按项目宠物与本地记录](https://github.com/ntd4996/agentpet)、[Clawd on Desk 的会话面板与 Codex 包导入](https://github.com/rullerzhou-afk/clawd-on-desk)、[官方 Hooks](https://learn.chatgpt.com/docs/hooks)。前两者对 Codex 的支持仍需区分 CLI、桌面来源与本机实测，不能直接复制兼容结论。

## 如何选择

| 方案 | 最主要的新增体验 | 首版能否不接模型 | 人物新素材需求 | 总体投入 |
|---|---|---|---|---|
| 1 零食收藏 | 可以互动、有东西留下 | 能 | 无，只需物品图 | 中 |
| 2 专注采购 | 陪伴过程有小故事 | 能 | 无，复用移动和挥手 | 中 |
| 3 文学社场景 | 有一个可布置的小空间 | 能 | 低，场景美术较多 | 中高 |
| 4 动作包 | 旧动作之外有新互动表演 | 能 | 高 | 中高 |
| 5 台词与日记 | 有口吻、记得共同经历 | 能；自由聊天另选 | 无 | 中；语音聊天高 |
| 6 项目纪念册 | 陪伴与实际工作有联系 | 能 | 无 | 手动低；自动高 |

投入是相对工作量，尚不是工期承诺；实际范围取决于承载方式、资产与桌面兼容验证。

**推荐组合：1 + 2，之后接入 3。** “专注结束 → 带回点心/小票 → 收入收藏 → 摆进文学社”能自然形成持续体验，原版动作始终保留。轻量固定台词作为这些玩法的配套内容；完整自由聊天和自动 Codex 联动后置。

第一步只需验证：原图能按原节奏播放；一次互动能反馈并存档；退出后原生宠物照常；重启后收藏仍在。没有通过这些检查前，不先投入大量新人物动画或模型服务。
